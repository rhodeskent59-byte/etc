Engine B's venv also lacks its pinned dev deps, so the suite can't run out of the box (Day 9). One worker's early "46 passed" figure was simply wrong and was corrected in place to 41.
- **U-3. Determinism is logic-deep, not byte-deep (Days 10, 29).** Timestamps (`firedAt`, `scannedAt`) differ run to run; fault *snapshots* are insertion-order-sensitive. Codes and severities are deterministic; serialized output is not.
- **U-4. HOLE-1 (Days 15, 21, 29).** Engine B's history query hardcodes `simulated = 0`; SIMULATOR-source readings that reach the real telemetry table present as real in history, and can lose their badge entirely when stale/degraded/down. Unfixed — live tree was read-only for this run.
- **U-5. The status label does not exist (Day 17).** No module, table, issuance, revocation, registry, or canonical caveat text. The $249 offer's spec says "report and label"; the live catalog and Lane G page say report only. A differentiator is currently unimplemented.
- **U-6. Evidence chain thins at render (Days 13, 20).** Rendered faults drop per-field source identity; no customer view renders outage history despite GAP data existing in both engines' APIs.
- **U-7. Environment fragility (coordinator observation).** The system-level pytest install used for early verifications disappeared mid-run (consistent with this workspace's known machine-swap behavior); final verifications ran in a scratch venv. The staging suites themselves are unaffected, but "run the tests" on this machine currently requires a venv bootstrap. Engine B's venv has the same class of problem (U-2).
- **U-8. Gateway is three proven components, not a gateway (Days 3, 7, 19).** Duplicate `LinkState` definitions (gateway_core vs watchdog), buffer speaks dict records, nothing wires ingest → buffer → watchdog end-to-end, ongoing outages aren't written by the buffer until reconnect. Thresholds (watchdog, provisioning) are unvalidated against real hardware — Runbook Gaps #4/#5 stand: no confirmed sensor count, no real gateway, no real telemetry.
- **U-9. Staging billing must-fix list (Day 29).** B5c (create path doesn't verify the approval chain), no approver allowlist/non-blank check, double-approval accepted. The funnel likewise accepts unbadged leads at the HTTP layer. The Day 2 provisioning prototype's TEST authority key sits in source — acceptable in staging, disqualifying if copied to production as-is. Buffer corruption handling crashes the reader rather than quarantining the bad line.
- **U-10. Runbook drift (Day 1).** The go-live runbook predates Chunks 10–16 being live; the staging-tier design (second instance vs second VM vs dry-run-only) was never decided; public hosting (Gap #2) remains open.
